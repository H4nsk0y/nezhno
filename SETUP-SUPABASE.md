# Подключение Supabase к «Найка»

Пока Supabase не подключён, сайт уже работает как чек-лист: записи сохраняются в текущем браузере. **Фоновые уведомления ещё не отправляются.** После подключения появятся синхронизация и серверная отправка.

## 1. Создать проект

1. Откройте [панель Supabase](https://supabase.com/dashboard). Нажмите **Sign in** и войдите, например через GitHub.
2. Если организаций ещё нет, нажмите **New organization**. Название — любое, например `Family`. Для начала выберите **Free**. Оплачивать тариф для первой настройки не требуется.
3. На странице проектов нажмите **New project**.
4. В **Organization** выберите созданную организацию.
5. В **Project name** введите `nezhno`.
6. В **Database Password** задайте сгенерированный сложный пароль и сохраните в менеджере паролей. Его не нужно присылать в чат.
7. В **Region** выберите европейский регион, например **Central EU / Frankfurt**, если он доступен; иначе другой ближайший европейский регион. Часовой пояс напоминаний задаётся в приложении и от региона БД не зависит.
8. Остальные параметры оставьте стандартными. Если доступны опции типа подключения, оставьте **Data API + Connection String**, обычный **Postgres**, а не экспериментальную альтернативу.
9. Нажмите **Create new project** и дождитесь готовности панели проекта.

На Free проект может приостанавливаться при низкой активности; если это случится, его нужно возобновить в панели. Это также остановит серверные напоминания. [Правила Supabase](https://supabase.com/docs/guides/platform/free-project-pausing).

## 2. Что прислать для подключения сайта

Пришлите эти значения текстом:

```text
Project URL: https://xxxxxxxxxxxxxxxxxxxx.supabase.co
Publishable key: sb_publishable_...
Project reference: xxxxxxxxxxxxxxxxxxxx
```

- **Project URL**: кнопка **Connect** в верхней части проекта → раздел для приложения / API, либо **Project Settings → Data API → Project URL**. Нужен адрес `https://…supabase.co`, не PostgreSQL connection string.
- **Publishable key**: **Project Settings → API Keys → Publishable and secret API keys → Publishable key**. Скопируйте значение `sb_publishable_…`. Если проект показывает старую схему ключей, подойдёт **Legacy API Keys → anon / public**.
- **Project reference / Project ID**: **Project Settings → General**, либо часть адреса панели после `/project/`. Она обычно совпадает с началом Project URL.

Это публичные параметры клиентского приложения. **Не присылайте** Database Password, `service_role`, `sb_secret_…`, VAPID private key или персональный access token Supabase. [Документация по ключам](https://supabase.com/docs/guides/getting-started/api-keys).

Также сообщите сумму одной награды и, при желании, имя для приветствия. Сейчас сумма 1 500 ₽ и приветствие «солнышко»; оба значения меняются в настройках.

Этих трёх параметров достаточно для конфигурации сайта, но они не дают права развернуть серверные функции. Для этого используется вход в Supabase CLI на вашем компьютере — секретный токен не нужно отправлять в чат. Остальные шаги ниже можно выполнить вместе после создания проекта.

## 3. Создать таблицы

1. В панели проекта откройте **SQL Editor**.
2. Нажмите **New query** / **+**.
3. Откройте файл [supabase/migrations/001_care.sql](supabase/migrations/001_care.sql) из репозитория и скопируйте весь его текст в редактор.
4. Нажмите **Run**.
5. В **Table Editor** должны появиться `care_state`, `care_subscriptions`, `care_deliveries`. В `care_state` уже будет одна строка с `id = 1`.

Не включайте публичные политики чтения и записи. Таблицы закрыты; приложение обращается к ним через функцию с приватным кодом.

## 4. Подготовить секреты

В терминале из папки проекта выполните:

```sh
node scripts/generate-secrets.mjs
```

Скрипт создаст локальный файл `.env.local`, исключённый из Git. В нём:

| Имя | Назначение |
|---|---|
| `CARE_ACCESS_TOKEN` | Приватный код для открытия семейных данных. Сохраните его в менеджере паролей. |
| `CRON_SECRET` | Отдельный секрет для запуска напоминаний сервером. |
| `VAPID_PUBLIC_KEY` | Публичная часть ключа Web Push. |
| `VAPID_PRIVATE_KEY` | Секретная часть ключа Web Push. |
| `VAPID_SUBJECT` | Контактный URL сайта для сервиса push. |
| `ALLOWED_ORIGIN` | `https://h4nsk0y.github.io`, без `/nezhno/` и без завершающего слеша. |

Не пересоздавайте VAPID-ключи при обычном обновлении: существующие подписки привязаны к ним.

## 5. Развернуть серверные функции

В терминале в папке проекта:

```sh
npx supabase login
```

CLI предложит открыть браузер и завершить вход. Выполните его самостоятельно. Затем, заменив `ВАШ_PROJECT_REFERENCE` на значение из шага 2:

```sh
npx supabase secrets set --env-file .env.local --project-ref ВАШ_PROJECT_REFERENCE
npx supabase functions deploy care-api --project-ref ВАШ_PROJECT_REFERENCE --no-verify-jwt
npx supabase functions deploy care-reminders --project-ref ВАШ_PROJECT_REFERENCE --no-verify-jwt
```

Docker для этих удалённых операций обычно не нужен. Если CLI предлагает сборку без Docker, используйте `--use-api` у команд `functions deploy`.

В панели **Edge Functions** должны появиться `care-api` и `care-reminders`. В **Edge Functions → Secrets** видны имена шести секретов. Их также можно внести вручную через **Add new secret → Name / Value → Save**. [Управление секретами](https://supabase.com/docs/guides/functions/secrets).

`--no-verify-jwt` нужен, потому что аккаунтов пользователей нет: каждая функция проверяет собственный сильный секрет. Это не открывает данные для посетителей без кода. Системный `SUPABASE_SERVICE_ROLE_KEY` / `SUPABASE_SECRET_KEYS` предоставляется самой платформой, его не нужно копировать в сайт.

## 6. Подключить планировщик

1. Откройте [supabase/setup-cron.sql](supabase/setup-cron.sql).
2. В новом запросе **SQL Editor** вставьте весь файл.
3. Замените `https://YOUR_PROJECT_REF.supabase.co` на ваш Project URL.
4. Замените `YOUR_RANDOM_CRON_SECRET_AT_LEAST_32_CHARACTERS` на значение `CRON_SECRET` из локального `.env.local`.
5. Нажмите **Run**. Эту версию запроса с секретом не публикуйте в GitHub.
6. Откройте **Integrations → Cron** (либо раздел **Cron** в панели) и проверьте, что задача `nezhno-reminders` включена.

Если расширения запрещено создавать из SQL Editor, включите `pg_cron` и `pg_net` в **Database → Extensions**, затем повторите запрос. Vault обычно уже доступен в проекте.

Cron запускается раз в минуту. Функция отправляет push только в 07:00, 10:00, 13:00, 16:00, 19:00 и 22:00 в часовом поясе приложения. Первые 10 минут каждого интервала используются для повторной попытки при временном сбое. Журнал предотвращает повторные успешные отправки одного интервала.

Секреты Vault создаются один раз. При изменении конфигурации обновляйте существующие записи Vault, а не создавайте одноимённые повторно. [Планирование Edge Functions](https://supabase.com/docs/guides/functions/schedule-functions).

## 7. Подключить сайт к проекту

Заполните `public/config.json`:

```json
{
  "supabaseUrl": "https://ВАШ_PROJECT_REFERENCE.supabase.co",
  "publishableKey": "sb_publishable_ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ"
}
```

После коммита в `main` GitHub Actions обновит Pages автоматически. Этот шаг я могу сделать по присланным публичным параметрам.

На сайте откройте **Настройки → Твоя приватная синхронизация**, введите `CARE_ACCESS_TOKEN` и нажмите **Подключить облако**. На первом устройстве локальный чек-лист загрузится в пустое облако. На втором устройстве будет загружена облачная версия. Если на двух устройствах уже появились разные записи, приложение предложит сохранить резервную копию и выбрать облачную версию вместо тихой перезаписи.

## 8. Установить на iPhone

1. В Safari откройте [Найка](https://h4nsk0y.github.io/nezhno/).
2. Откройте меню **Поделиться** (квадрат со стрелкой вверх; положение зависит от версии Safari).
3. Выберите **На экран «Домой»** / **Add to Home Screen**. При необходимости прокрутите список действий.
4. Если есть переключатель **Открывать как веб-приложение**, включите его.
5. Нажмите **Добавить**.
6. Закройте вкладку и откройте «Найка» с новой иконки.
7. Введите приватный код в настройках внутри установленного приложения. Установленная версия может иметь отдельное хранилище от вкладки Safari.
8. Нажмите **Включить на этом устройстве** и в запросе iOS выберите **Разрешить**.
9. Нажмите **Проверить push**. Должно прийти «Найка на связи 🌷».
10. Проверьте доставку при свёрнутом приложении и заблокированном экране. Затем дождитесь ближайшего планового интервала.

Web Push на iPhone поддерживается для приложений на экране «Домой», начиная с iOS 16.4. [Документация WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).

Если уведомление не появилось, проверьте **Настройки iPhone → Уведомления → Найка**, доступ к интернету, режим «Фокусирование» и сводку уведомлений. На сервере проверьте **Edge Functions → care-reminders → Logs**, историю Cron и `care_deliveries`. Успешный запуск Cron сам по себе не доказывает успешную доставку HTTP-запроса или push — проверьте результат функции и фактический показ на телефоне.

В уведомлениях нет названий лекарств: на заблокированном экране появляется только приглашение проверить список. Начальное расписание с препаратами входит в публичный код по запросу; персональные отметки и изменения после подключения хранятся в закрытой БД.
