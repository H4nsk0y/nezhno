# Найка 🌷

Небольшое приложение для ежедневного чек-листа, недельного расписания и наград за заботу о себе.

**Сайт:** https://h4nsk0y.github.io/nezhno/

## Что умеет

- Пять предварительно внесённых препаратов, семь отметок в день. Для витамина D оставлена доза «по назначению»; часы приёма не придуманы.
- Отдельные отметки каждого приёма, подтверждение полностью заполненного дня, история по неделям.
- Редактируемые дни недели, количество приёмов, необязательные часы и период назначения.
- Одна награда за каждые 10 заполненных дней, без требования непрерывной серии. Wildberries или копилка путешествия. Сумма меняется в настройках; начальное значение 1 500 ₽.
- PWA для iPhone и Android, мягкие анимации с поддержкой reduced motion.
- Хранение в браузере до подключения Supabase, затем облачная синхронизация с защитой от перезаписи при конфликте и резервное сохранение на устройстве при отсутствии сети.
- Серверные Web Push в 07:00, 10:00, 13:00, 16:00, 19:00, 22:00 по настроенному часовому поясу. Заполненный день больше не напоминает о себе.

Сайт не назначает лечение, не оплачивает покупки и не переводит деньги. Напоминания предлагают проверить чек-лист, а не принимать все препараты каждые три часа.

## Запуск

```sh
npm ci
npm run dev
npm test
npm run build
```

Статическая сборка лежит в `dist`. GitHub Actions публикует её в Pages при изменении `main`.

## Подключение облака

Пошаговая инструкция: [SETUP-SUPABASE.md](SETUP-SUPABASE.md).

В `public/config.json` допускаются только Project URL и publishable/anon key. Секретный код, service role и VAPID private key никогда не помещаются в сайт или GitHub.

Регистрации пользователей нет. Один криптографически случайный семейный код хранится в секрете Supabase и вводится на каждом устройстве. Прямое чтение таблиц закрыто RLS и отзывом прав `anon` / `authenticated`. Сервер сравнивает код перед доступом через service role. Это доступ по владению кодом: не пересылайте его посторонним.

`care-api` читает/сохраняет состояние с optimistic concurrency (`revision`), регистрирует push-подписки и отправляет тестовое сообщение. `care-reminders` вызывается Cron с отдельным секретом, учитывает часовой пояс, исключает уже заполненные дни, удаляет отозванные подписки. Уникальный журнал отправок и условный захват повторной попытки предотвращают обычные дубли при параллельных вызовах. Сбой между доставкой push и записью результата может вызвать повтор; одинаковый notification tag заменяет такое уведомление.

## Проверка серверного кода

```sh
npx deno check --node-modules-dir=auto supabase/functions/care-api/index.ts supabase/functions/care-reminders/index.ts
npx deno test --node-modules-dir=auto --allow-env supabase/functions/_shared/core_test.ts
```

Настоящая доставка push и RLS на размещённом проекте должны быть проверены после подключения Supabase. Уведомления зависят от интернета и разрешений iOS; Focus и настройки сводки могут повлиять на показ. При офлайне незасинхронизированное завершение дня ещё не известно серверу.
